# 代码优化工作流程

> **第一原则**：简洁而不脆弱，复用而不复杂

---

## 阶段一：扫描冗余热点

### 1.1 识别重复代码

使用 grep 搜索以下常见重复模式：

**前端搜索**：

```bash
# localStorage 重复操作
grep -r "localStorage\." src/ --include="*.vue" --include="*.ts"

# 重复的错误处理模式
grep -r "catch (error" src/ --include="*.vue" --include="*.ts"

# 重复的类型判断
grep -r "\.includes(" src/ --include="*.vue" --include="*.ts"
```

**后端搜索**：

```bash
# 响应模式
grep -r "res.status" server/routes/ --include="*.js"

# 错误处理
grep -r "catch (error)" server/ --include="*.js"

# 权限检查
grep -r "req.user.role" server/ --include="*.js"
```

### 1.2 建立"可删清单"

按以下标准判定冗余：

- ✅ 重复出现 ≥2 次的逻辑/结构必须抽象或移除
- ✅ 无效配置/未使用的导入
- ✅ 过度封装（增加调用方学习成本 >10%）
- ✅ 硬编码的魔法数字

---

## 阶段二：注入防御机制 + 提取复用单元

### 2.1 选择重构策略

| 策略         | 适用场景           | 示例                     |
| ------------ | ------------------ | ------------------------ |
| **辅助函数** | 完全相同的代码块   | `_saveAuthData()`        |
| **配置常量** | 重复的判断逻辑     | `RISK_LEVEL_CONFIG`      |
| **工厂函数** | 重复的对象创建     | `createTaskFromStatus()` |
| **中间件**   | 后端重复的请求处理 | 权限检查、错误捕获       |

### 2.2 辅助函数模板

```typescript
/**
 * [功能描述]
 * @param data - [参数说明]
 * @returns [返回值说明]
 *
 * 复用说明：[说明该函数在哪些场景下可复用]
 * 防错机制：[说明边界检查、默认值等]
 */
function helperName(data: DataType): ReturnType {
  // 边界检查
  if (!data) return defaultValue;

  // 核心逻辑
  // ...
}
```

### 2.3 配置常量模板

```typescript
// [配置用途说明]
const CONFIG_NAME = [
  { key: 'value1', ... },
  { key: 'value2', ... },
] as const;

// 查找函数（支持默认值）
const findConfig = (search: string) =>
  CONFIG_NAME.find(c => c.keywords.some(k => search.includes(k)))
  ?? DEFAULT_CONFIG;
```

## 阶段三：执行重构

// turbo

1. **先添加**辅助函数/配置常量（不修改现有逻辑）

2. **逐个替换**重复代码为函数调用

3. **每次修改后**检查 IDE 无 lint 错误

4. **验证**功能等价性

---

## 阶段四：验证稳定性

### 4.1 必须通过的测试

- [ ] 正常路径测试：主流程功能正常
- [ ] 边界值测试：空值、极大值、极小值
- [ ] 异常路径测试：模拟失败场景

### 4.2 量化指标

优化完成后需提供：

- **代码行减少率**：目标 ≥25%
- **异常捕获覆盖率**：目标 ≥90%
- **模块复用指数**：核心模块复用率提升 ≥50%

---

## 优化原则总结

### ✅ 必须遵守

| 原则       | 说明                                   |
| ---------- | -------------------------------------- |
| 简洁≠脆弱  | 所有删减必须通过异常路径测试验证       |
| 复用有契约 | 公共模块必须附带清晰接口文档           |
| 行为强一致 | 优化前后在正常与异常输入下输出完全一致 |
| 可测量改进 | 提供量化指标证明优化效果               |

### ❌ 禁止行为

| 禁止项         | 原因                           |
| -------------- | ------------------------------ |
| "聪明代码"     | 优先清晰、显式、易复用，非炫技 |
| 破坏模块独立性 | 禁止引入隐式耦合               |
| 过度封装       | 调用方学习成本不得增加 >10%    |
| 无记录删除     | 删除代码必须保留理由于版本历史 |
