# 原型提示词生成器

## 概述

生成用于 UI/UX 原型创建的全面、生产就绪的提示词。将用户需求转化为包含设计系统、调色板、组件规格、布局结构和实现指南的详细技术规格。输出的提示词结构化，便于 AI 工具或开发人员生成 HTML/CSS/React 原型。

---

## 工作流

### 步骤 1：收集需求

通过有针对性的问题收集必要信息：

**应用类型 & 目的**：

- 什么类型的应用？（企业工具、电商、社交媒体、仪表板）
- 目标用户是谁？
- 主要用例和工作流是什么？

**平台 & 上下文**：

- 目标平台：iOS、Android、Web、微信小程序或跨平台？
- 设备：手机、平板、桌面还是响应式？
- 视口尺寸（如 iPhone 375px，桌面 1200px）

**设计偏好**：

- 设计风格：企业微信、iOS 原生、Material Design、Ant Design Mobile 或自定义？
- 品牌颜色或视觉偏好？
- 设计参考或灵感？

**功能需求**：

- 需要的关键页面和功能
- 导航结构（标签、抽屉、堆栈导航）
- 要显示的数据（指标、列表、表单、媒体）
- 用户交互（点击、滑动、长按等）

**每次问 2-3 个问题**，避免压倒用户。许多细节可从上下文推断或用合理默认值填充。

### 步骤 2：选择设计系统

根据收集的需求，从参考资料中选择适当的设计系统：

**企业微信风格**：

- **适用**：中国企业应用、工作管理工具、B2B 平台、内部业务系统
- **特点**：简洁专业、科技蓝主色、清晰信息层级
- **受众**：中国商务用户、企业环境

**iOS 原生风格**：

- **适用**：iOS 特定应用、Apple 生态集成、面向 iPhone/iPad 用户的应用
- **特点**：极简、宽敞布局、San Francisco 字体、系统颜色
- **受众**：Apple 用户、消费者应用、内容聚焦应用

**Material Design 风格**：

- **适用**：Android 优先应用、Google 生态集成、使用 Material UI 的跨平台应用
- **特点**：大胆图形、高度系统、波纹效果、Roboto 字体
- **受众**：Android 用户、Google 服务、开发者工具

**Ant Design Mobile 风格**：

- **适用**：复杂数据录入和表单的企业移动应用
- **特点**：效率导向、一致性组件、适合业务应用
- **受众**：业务用户、企业移动应用、数据密集界面

请使用 `view_file` 读取完整设计系统规格：`{工作区根目录}/.agent/resources/prototype-prompt-generator/references/design-systems.md`

### 步骤 3：构建提示词

使用提示词结构模板，构建包含以下部分的全面提示词：

1. **角色定义** - 定义原型相关的专业知识
2. **任务描述** - 清晰说明要构建什么和设计风格
3. **技术栈规格** - 所有技术、框架和资源
4. **视觉设计要求** - 调色板、UI 风格特征、布局结构
5. **实现细节** - 技术具体事项
6. **Tailwind 配置** - 如使用 Tailwind CSS
7. **内容结构 & 层级** - 页面结构树形可视化
8. **特殊要求** - 独特考虑
9. **输出格式** - 确切交付物规格

请使用 `view_file` 读取详细模板：`{工作区根目录}/.agent/resources/prototype-prompt-generator/references/prompt-structure.md`

### 步骤 4：填充具体内容

用具体值替换所有模板占位符：

**用精确规格替换模糊术语**：

- ❌ "使用蓝色" → ✅ "主色：#3478F6（科技蓝）"
- ❌ "按钮圆角" → ✅ "圆角：4px（Tailwind: rounded）"
- ❌ "添加间距" → ✅ "卡片间距：12px，页面边距：16px"

**使用真实内容，而非占位符**：

- ❌ "Lorem ipsum" → ✅ "客户总数：14，今日新增：1，今日收入：¥0.00"
- ❌ "[公司名称]" → ✅ "某某保险公司"
- ❌ "功能 1、功能 2、功能 3" → ✅ "客户联系、客户朋友圈、客户群"

**指定所有测量值**：

- 组件高度（44px、50px、64px）
- 字体大小（13px、15px、16px、18px）
- 间距值（8px、12px、16px、24px）
- 图标大小（24px、32px、48px）

**定义所有状态**：

- 正常：基础颜色和样式
- 悬停：如适用（桌面）
- 激活/按下：透明度或背景变化
- 禁用：灰色并降低透明度
- 选中：高亮颜色（通常是品牌主色）

### 步骤 5：质量保证

在呈现最终提示词前，按检查清单验证：

**完整性检查**：

- [ ] 角色清晰定义
- [ ] 任务明确说明构建内容和设计风格
- [ ] 所有技术栈组件带版本/CDN
- [ ] 完整调色板带所有颜色的十六进制代码
- [ ] 所有 UI 组件带精确尺寸和样式
- [ ] 页面布局完整描述带精确测量
- [ ] 提供实际真实内容（无 Lorem Ipsum 或 [名称] 占位符）

**清晰性检查**：

- [ ] 无模糊术语（如"一些填充"、"漂亮颜色"）
- [ ] 所有测量值带单位（px、rem、%、vh 等）
- [ ] 所有颜色带十六进制代码
- [ ] 组件状态已描述

**特异性检查**：

- [ ] 设计系统明确命名
- [ ] 视口尺寸已提供
- [ ] 排版比例已定义
- [ ] 交互行为已记录

### 步骤 6：展示和迭代

**向用户展示生成的提示词**并简要说明：

- 选择了哪个设计系统及原因
- 做出的关键设计决策
- 应用的假设或默认值
- 如何使用提示词

**提供精炼选项**：

- "要调整任何颜色或间距吗？"
- "要添加更多页面或功能吗？"
- "要更改设计系统吗？"

## 最佳实践

1. **默认高质量**：即使用户提供最少需求，也生成全面提示词
2. **智能使用设计系统默认值**：需求模糊时应用完整设计系统
3. **清晰优于简洁**：更长、更详细的提示词产生更好的原型
4. **移动优先思维**：始终考虑安全区域、触摸目标大小、拇指可及区域
5. **平衡灵活性和特异性**：核心元素具体，实现细节灵活
6. **考虑完整用户旅程**：包括入口点、主工作流、边界情况、出口点
7. **提供上下文而非仅规格**：解释设计决策的"为什么"
8. **验证技术可行性**：确保 CSS/Tailwind 类能实现描述的设计
9. **使其可执行**：提示词应能立即实现
10. **预见问题**：在提示词中处理常见不确定性
