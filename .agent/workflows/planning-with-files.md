# 使用文件进行规划 (Planning with Files)

像 Manus 一样工作：使用持久化的 Markdown 文件作为你的"磁盘上的工作记忆"。

## 快速开始

在进行**任何**复杂任务之前：

1. 在工作目录中**创建 `task_plan.md`**
2. 使用复选框**定义阶段**
3. **每个阶段后更新** - 标记 [x] 并更改状态
4. **决策前阅读** - 在注意力窗口中刷新目标

## 三文件模式 (The 3-File Pattern)

对于每个非微不足道的任务，创建三个文件：

| 文件               | 用途           | 何时更新   |
| ------------------ | -------------- | ---------- |
| `task_plan.md`     | 跟踪阶段和进度 | 每个阶段后 |
| `notes.md`         | 存储发现和研究 | 研究期间   |
| `[deliverable].md` | 最终输出       | 完成时     |

## 核心工作流

```
循环 1: 创建具有目标和阶段的 task_plan.md
循环 2: 研究 → 保存到 notes.md → 更新 task_plan.md
循环 3: 阅读 notes.md → 创建交付物 → 更新 task_plan.md
循环 4: 交付最终输出
```

### 详细循环

**在每个主要动作之前：**

```bash
Read task_plan.md  # 在注意力窗口中刷新目标
```

**每个阶段之后：**

```bash
Edit task_plan.md  # 标记 [x]，更新状态
```

**存储信息时：**

```bash
Write notes.md     # 不要填充上下文，存储在文件中
```

## task_plan.md 模板

对于任何复杂任务，**首先**创建此文件：

```markdown
# 任务计划：[简短描述]

## 目标

[描述最终状态的一句话]

## 阶段

- [ ] 阶段 1：规划和设置
- [ ] 阶段 2：研究/收集信息
- [ ] 阶段 3：执行/构建
- [ ] 阶段 4：审查和交付

## 关键问题

1. [要回答的问题]
2. [要回答的问题]

## 已做出的决策

- [决策]：[理由]

## 遇到的错误

- [错误]：[解决方案]

## 状态

**当前处于阶段 X** - [我现在正在做什么]
```

## notes.md 模板

用于研究和发现：

```markdown
# 笔记：[主题]

## 来源

### 来源 1：[名称]

- URL：[链接]
- 要点：
  - [发现]
  - [发现]

## 综合发现

### [类别]

- [发现]
- [发现]
```

## 关键规则

### 1. 始终首先创建计划

永远不要在没有 `task_plan.md` 的情况下开始复杂任务。这是不可商量的。

### 2. 决策前阅读

在任何重大决策之前，阅读计划文件。这将目标保持在你的注意力窗口中。

### 3. 行动后更新

完成任何阶段后，立即更新计划文件：

- 用 [x] 标记已完成的阶段
- 更新状态部分
- 记录遇到的任何错误

### 4. 存储，不要填充

大输出进入文件，而不是上下文。只在工作记忆中保留路径。

### 5. 记录所有错误

每个错误都进入"遇到的错误"部分。这为未来的任务建立了知识。

## 何时使用此模式

**在以下情况使用三文件模式：**

- 多步骤任务（3 个以上步骤）
- 研究任务
- 构建/创建某物
- 跨越多个工具调用的任务
- 任何需要组织的事情

**以下情况跳过：**

- 简单问题
- 单文件编辑
- 快速查找

## 避免的反模式

| 不要                      | 应该                     |
| ------------------------- | ------------------------ |
| 使用 TodoWrite 进行持久化 | 创建 `task_plan.md` 文件 |
| 声明一次目标然后忘记      | 每次决策前重读计划       |
| 隐藏错误并重试            | 将错误记录到计划文件     |
| 将所有内容填充在上下文中  | 将大内容存储在文件中     |
| 立即开始执行              | **首先**创建计划文件     |
