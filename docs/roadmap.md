## 一、项目现状总评

项目已具备完整的核心功能闭环：**用户注册/登录 → 患者管理 → 影像上传 → AI分析 → 结果展示 → PDF报告导出 → 订阅支付**。技术栈选型合理（Vue3 + Quasar + Node.js + Sequelize），第三方集成丰富（阿里云认证、腾讯云邮件、通义千问AI、易支付）。但在**安全加固、用户体验细化、功能深度、视觉品质**等方面仍有大量提升空间。

### 技术栈概览

| 层级           | 技术选型                 |
| :------------- | :----------------------- |
| **前端框架**   | Vue 3 + TypeScript       |
| **UI 组件库**  | Quasar Framework v2.16.0 |
| **构建工具**   | Vite                     |
| **状态管理**   | Pinia                    |
| **图表库**     | ECharts                  |
| **移动端**     | Capacitor                |
| **后端运行时** | Node.js + Express 5      |
| **数据库 ORM** | Sequelize + MySQL        |
| **认证服务**   | 阿里云号码认证           |
| **邮件服务**   | 腾讯云 SES               |
| **AI 服务**    | 通义千问 VL              |
| **支付平台**   | 易支付                   |
| **图像处理**   | sharp                    |
| **部署方案**   | Docker + Nginx           |

## 二、安全加固（P0 紧急）

> [!CAUTION]
> 以下安全问题已在 `深度代码审查报告_2026-02-06.md` 中详细论证（H-01 至 H-14），属于**必须立即修复**的项目。任何对外部署前都必须完成此阶段。

| 编号 | 问题                        | 当前状态                                                             | 改进方案                                                    | 可行性                            |
| :--: | --------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- | --------------------------------- |
|  S1  | **患者数据越权访问**        | `server/routes/patients.js` 权限校验被注释掉，任意用户可查看所有患者 | 恢复基于 `created_by` 的数据隔离，增加科室级/医院级权限模型 | ⭐⭐⭐ 高，代码仅需取消注释+补全  |
|  S2  | **静态资源无鉴权**          | `/uploads`、`/reports` 目录直接 `express.static` 公开                | 改为通过 API 接口下发文件流，中间件校验 Token 权限          | ⭐⭐⭐ 高，改动量中等             |
|  S3  | **Token 存储不安全**        | Access Token + Refresh Token 均存 localStorage                       | 将 Refresh Token 迁移至 HttpOnly Cookie，防止 XSS 窃取      | ⭐⭐ 中，需前后端同步改造         |
|  S4  | **缺少安全头**              | 仅手动设置 `X-Content-Type-Options`                                  | 引入 `helmet` 中间件，启用 CSP、HSTS、X-Frame-Options 等    | ⭐⭐⭐ 高，npm install + 一行代码 |
|  S5  | **输入校验薄弱**            | 手动 `if` 判断，容易遗漏                                             | 引入 `Joi` 或 `Zod` 统一请求参数校验                        | ⭐⭐ 中，需逐个路由改造           |
|  S6  | **分析接口 IDOR**           | `/api/analyze/:taskId` 等无鉴权与归属校验                            | 为分析查询接口增加 `authenticate` + 归属过滤                | ⭐⭐⭐ 高，改动量小               |
|  S7  | **系统管理接口未鉴权**      | `/api/system/*` 可公开访问                                           | 增加 `authenticate` + `authorize('admin')`                  | ⭐⭐⭐ 高，改动量小               |
|  S8  | **JWT Secret 不安全默认值** | 环境变量缺失时仍可运行                                               | 启动时强制校验+拆分 Access/Refresh Secret                   | ⭐⭐⭐ 高，几行代码               |
|  S9  | **验证码明文写日志**        | `console.log` 明文输出验证码                                         | 删除明文日志，仅输出 `biz_id`                               | ⭐⭐⭐ 高，删除一行代码           |
| S10  | **支付幂等性缺失**          | 回调重放可导致积分重复发放                                           | 事务内加行锁 + 原子更新                                     | ⭐⭐ 中，需理解支付流程           |

### 7.2 关键优化建议

#### 🔴 建议调整的 8 个问题

1. **第一阶段时间偏紧**：原计划 1-2 周完成安全加固，但 S3（Token 迁移 HttpOnly Cookie）涉及前后端同步改造，建议预留 2-3 周
2. **F3/F7 不应列入可执行计划**：通义千问 VL 不支持 Grad-CAM 输出，本地推理工程量远超预期，建议从路线图中移至"探索性研究"板块
3. **报告系统需先完成"去 Mock 化"**：F13/F14/F15 的前提是报告模块从 Mock 迁移到真实实现，应在第二阶段末期完成
4. **第二阶段任务过载**：原方案包含 12 个任务（3-4 周），按每任务平均 2 天估算至少需要 5 周。建议拆分为 2a（核心功能）+ 2b（体验优化）
5. **T15（Docker）标记已完成**：已有完整的部署文档和 Dockerfile，应从待办中移除
6. **U1（暗色模式）已部分实现**：`themeStore.ts` 已存在，只需完善各页面适配
7. **T12（国际化）ROI 极低**：当前项目面向中国医疗场景，16 个页面+18 个组件的中文硬编码提取工作量巨大，建议无限期推迟
8. **缺少数据库性能优化项**：随着数据量增长，需添加**索引优化**和**分页查询标准化**到第三阶段

## 八、总结

CervixDetectAI 已经建立了一个功能完整的 MVP 产品。未来发展的关键方向是：

1. **安全第一** — 医疗数据敏感度极高，权限和数据保护必须立即修复
2. **体验精细化** — 从骨架屏、动画过渡、暗色模式到新手引导，打磨每一个用户触点
3. **AI 能力纵深** — 批量检测、历史对比、置信度校准，让 AI 不只是"出结果"，更要"讲清楚"
4. **协作与合规** — 多人协作、审核流程、审计日志，满足医疗信息系统的合规要求
5. **工程化保障** — 测试覆盖、CI/CD、结构化日志，确保产品稳定可靠地迭代

> [!IMPORTANT]
> 建议在每个阶段结束时进行**里程碑评审**，根据实际进展动态调整后续阶段的范围和优先级。不要"贪多求全"，每个阶段聚焦 5-8 个核心任务。
