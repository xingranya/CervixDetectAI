## MVC架构与模块划分
CervixDetectAI后端严格遵循MVCModel-View-Controller架构模式，尽管在API服务中“View”层被省略。其核心模块划分如下：
- **Model (模型)**: 位于`server/models`目录下，使用Sequelize ORM定义所有数据库实体及其关系。每个模型文件如`User.js`, `Study.js`定义了数据表的结构、字段、约束和钩子Hooks。
- **Controller (控制器)**: 路由处理逻辑内联在`server/routes`目录下的各个路由文件中如`auth.js`, `analyze.js`。这些文件接收HTTP请求，调用服务层进行业务处理，并返回响应。
- **Service (服务)**: 位于`server/services`目录下，封装了核心业务逻辑。`qwenService.js`负责与通义千问API交互，`sms.service.js`负责与阿里云短信服务交互。这确保了业务逻辑与路由逻辑的分离。
这种分层使得代码职责清晰，`routes`负责请求/响应，`services`负责业务规则，`models`负责数据持久化。

## 数据模型与关系
系统定义了多个核心数据模型，通过Sequelize的关联关系Associations紧密连接。
### 核心模型字段
#### User (用户)
- `id`: 主键
- `username`: 用户名 (唯一)
- `email`: 邮箱 (唯一)
- `password_hash`: 加密后的密码
- `real_name`: 真实姓名
- `phone`: 手机号
- `role`: 角色 (admin, doctor, user)
- `status`: 状态 (active, disabled)
#### Study (病例)
- `id`: 主键
- `study_id`: 病例ID (唯一)
- `patient_id`: 外键，关联患者
- `user_id`: 外键，关联创建用户
- `study_date`: 检查日期
- `study_type`: 检查类型
- `status`: 状态 (pending, uploaded, processing, completed, failed)
#### AnalysisTask (分析任务)
- `id`: 主键
- `task_id`: 任务ID (唯一)
- `study_id`: 外键，关联病例
- `user_id`: 外键，关联发起用户
- `status`: 任务状态 (PENDING, PROCESSING, SUCCESS, FAILED)
- `progress`: 进度 (0-100)
#### AnalysisResult (分析结果)
- `id`: 主键
- `task_id`: 外键，关联分析任务 (唯一)
- `study_id`: 外键，关联病例
- `diagnosis`: 诊断结果
- `confidence`: 置信度 (0-1)
- `risk_level`: 风险等级 (low, medium, high, critical)
- `recommendations`: 医疗建议 (JSON)
- `detailed_report`: 详细报告
#### Patient (患者)
- `id`: 主键
- `patient_id`: 患者ID (唯一)
- `name`: 姓名
- `gender`: 性别
- `created_by`: 外键，关联创建用户
#### MedicalReport (医疗报告)
- `id`: 主键
- `report_id`: 报告ID (唯一)
- `study_id`: 外键，关联病例
- `analysis_result_id`: 外键，关联分析结果
- `file_path`: PDF报告文件路径
- `status`: 报告状态 (draft, pending_review, approved, rejected)

## API端点设计

系统API采用RESTful风格设计，所有端点均以`/api`为前缀。

### 认证相关端点
- `POST /api/auth/register`: 邮箱注册
- `POST /api/auth/login`: 邮箱登录
- `POST /api/auth/refresh`: 刷新JWT令牌
- `POST /api/auth/logout`: 用户登出
- `GET /api/auth/me`: 获取当前用户信息
- `POST /api/auth/sms/send-code`: 发送短信验证码
- `POST /api/auth/sms/login`: 短信验证码登录
- `POST /api/auth/sms/register`: 短信验证码注册
- `POST /api/auth/sms/reset-password`: 短信验证码重置密码

### 病例与分析相关端点
- `POST /api/analyze`: 上传图像并创建分析任务
- `GET /api/analyze/:taskId`: 查询分析任务状态
- `GET /api/analyze/study/:studyId`: 根据病例ID查询分析结果
- `GET /api/studies`: 获取病例列表
- `POST /api/studies`: 创建新病例
- `GET /api/studies/:id`: 获取病例详情
- `GET /api/reports/:id/download`: 下载PDF报告

### 响应格式
所有API响应均采用统一的JSON格式：
```json
{
  "success": true,
  "message": "操作成功",
  "data": { /* 具体数据 */ }
}
```
或在出错时：
```json
{
  "success": false,
  "message": "错误信息",
  "error": "错误详情"
}
```

## 业务逻辑分层

系统的业务逻辑被清晰地封装在`services`层，实现了与路由的解耦。

### AI分析逻辑 (`qwenService.js`)
`QwenService`类封装了与通义千问视觉大模型交互的全部逻辑。
1.  **图像处理**: `imageToBase64`方法将上传的图像文件转换为Base64编码的Data URL。
2.  **API调用**: `analyzeImage`方法构建符合通义千问API要求的请求体，包含系统提示词（`SYSTEM_PROMPT`）和图像数据，并通过`axios`发送请求。
3.  **结果处理**: 接收API响应后，解析JSON格式的分析结果，进行字段验证和标准化，确保返回结构一致。
4.  **错误处理与重试**: 实现了完善的错误处理机制，能识别网络错误、API限流等，并进行指数退避重试。

### 短信服务逻辑 (`sms.service.js`)
`AliyunSmsService`类封装了阿里云短信服务的调用。
1.  **客户端创建**: `createClient`方法使用环境变量中的AccessKey初始化阿里云SDK客户端。
2.  **验证码生成**: `generateCode`方法生成6位随机数字验证码。
3.  **短信发送**: `sendVerifyCode`方法调用阿里云API发送短信，并将验证码记录在数据库中。
4.  **格式验证**: `validatePhoneNumber`方法验证手机号格式是否符合中国大陆规范。

## 中间件机制

中间件是Express应用的核心，用于在请求-响应周期中执行代码。

### JWT认证中间件 (`middleware/auth.js`)
- `authenticate`: 核心中间件，用于保护需要认证的路由。
  1.  从请求头`Authorization`中提取JWT令牌。
  2.  使用`jwt.verify`验证令牌的有效性和签名。
  3.  检查令牌类型是否为`access`。
  4.  根据令牌中的`userId`查询数据库，获取用户信息。
  5.  验证用户状态是否为`active`。
  6.  将用户信息附加到`req.user`对象，供后续路由处理函数使用。
- `authorize`: 角色授权中间件，接受角色列表作为参数，检查`req.user.role`是否在允许的列表中。
- `optionalAuth`: 可选认证中间件，尝试验证令牌，如果成功则附加用户信息，失败则继续执行，用于需要区分登录/未登录状态的场景。

### JWT工具 (`utils/jwt.js`)
该模块提供了JWT令牌的生成和验证功能。
- `generateAccessToken`: 为用户生成有效期较短的访问令牌（access token），包含用户ID、用户名、邮箱、角色等信息。
- `generateRefreshToken`: 生成有效期较长的刷新令牌（refresh token），仅包含用户ID。
- `verifyToken`: 验证令牌并返回解码后的payload。
- `extractToken`: 从请求头中提取Bearer令牌。

## 通义千问视觉大模型集成

系统通过`qwenService.js`服务与通义千问视觉大模型深度集成，实现宫颈细胞学图像的AI分析。

### 集成流程
1.  **环境配置**: 在`.env`文件中配置`QWEN_API_KEY`、`QWEN_API_URL`和`QWEN_MODEL`。
2.  **服务初始化**: `QwenService`构造函数读取环境变量并创建`axios`实例，配置API密钥。
3.  **图像上传**: 当用户上传图像时，`analyze.js`路由调用`qwenService.analyzeImage(imagePath)`。
4.  **API调用**: `analyzeImage`方法将图像转为Base64，构建包含系统提示词和图像的请求体，发送至通义千问API。
5.  **结果解析**: 服务接收响应，解析JSON结果，并进行标准化处理，最终返回结构化的诊断信息。

### 提示词工程
系统使用精心设计的`SYSTEM_PROMPT`来指导大模型的分析行为，明确其角色（宫颈细胞学病理专家）、技能、目标和输出格式，确保分析的专业性和一致性。

## 阿里云短信服务集成

系统通过`sms.service.js`服务集成阿里云短信服务，用于用户注册、登录和密码重置的验证码发送。

### 集成流程
1.  **环境配置**: 在`.env`文件中配置`ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET`、`ALIYUN_SMS_SIGN_NAME`和`ALIYUN_SMS_TEMPLATE_CODE`。
2.  **服务初始化**: `AliyunSmsService`构造函数使用AccessKey初始化阿里云SDK客户端。
3.  **验证码发送**: 当用户请求发送验证码时，`sms-auth.js`路由调用`smsService.sendVerifyCode(phone)`。
4.  **API调用**: 服务生成验证码，调用阿里云`sendSmsVerifyCode`接口发送短信。
5.  **记录存储**: 发送成功后，将手机号、验证码、过期时间等信息存入数据库的`sms_codes`表，用于后续验证。

### 安全控制
- **频率限制**: 同一手机号60秒内不能重复发送。
- **次数限制**: 同一手机号每日最多发送10次。
- **状态检查**: 注册时检查手机号是否已存在，重置密码时检查手机号是否已注册。

## 安全机制

系统通过多层机制保障API安全。

### JWT认证与授权
- 所有敏感API端点（如`/api/analyze`, `/api/studies`）均使用`authenticate`中间件保护。
- 通过`authorize('admin')`等中间件实现基于角色的访问控制（RBAC），确保用户只能访问其权限范围内的资源（例如，普通用户只能查看自己创建的病例）。
- 使用短有效期的access token和长有效期的refresh token组合，平衡安全性和用户体验。

### 输入验证
- 在路由层对所有请求参数进行基础验证（如必填、格式）。
- 在模型层使用Sequelize的`validate`选项进行数据校验（如邮箱格式）。

### 数据库安全
- 敏感字段（如`password_hash`）在数据库中加密存储。
- 使用Sequelize的`paranoid: true`选项实现软删除，避免数据永久丢失。
- 通过外键约束和`ON UPDATE CASCADE`、`ON DELETE RESTRICT`等规则维护数据完整性。

### 其他安全措施
- 短信验证码的发送频率和次数限制，防止短信轰炸。
- 服务器端不返回明文密码，响应中排除`password_hash`字段。
