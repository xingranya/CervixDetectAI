## 字段定义

AnalysisTask模型定义了分析任务的核心数据结构，包含以下字段：

- **id**: BIGINT类型，主键，自增，唯一标识每个分析任务记录。
- **task_id**: STRING(50)类型，非空，具有唯一约束，存储系统生成的全局唯一任务标识符。
- **study_id**: BIGINT类型，非空，外键引用studies表的id字段，关联到具体的医学检查记录，更新时级联，删除时限制。
- **user_id**: BIGINT类型，非空，外键引用users表的id字段，关联到创建任务的用户，更新时级联，删除时限制。
- **status**: ENUM枚举类型，可选值为'PENDING'(待处理)、'PROCESSING'(处理中)、'SUCCESS'(成功)、'FAILED'(失败)，非空，默认值为'PENDING'。
- **progress**: INTEGER类型，非空，表示任务处理进度，范围为0-100的整数，默认值为0，并通过min和max验证器确保数据有效性。
- **ai_model_version**: STRING(50)类型，可为空，用于记录执行分析任务时所使用的AI模型版本号。
- **processing_time**: INTEGER类型，可为空，注释为“处理耗时（毫秒）”，用于记录任务处理所花费的时间（毫秒）。
- **error_message**: TEXT类型，可为空，用于在任务失败时存储详细的错误信息。
- **retry_count**: INTEGER类型，非空，默认值为0，用于记录任务失败后的重试次数。
- **started_at**: DATE类型，可为空，用于记录任务开始处理的时间戳。
- **completed_at**: DATE类型，可为空，用于记录任务完成（无论成功或失败）的时间戳。

## 索引配置

AnalysisTask模型配置了多个数据库索引以优化查询性能：

- **唯一索引 (Unique Index)**: 在`task_id`字段上创建了唯一索引，确保每个任务ID的全局唯一性，这是快速通过任务ID查找任务记录的关键。
- **普通索引 (Regular Indexes)**:
  - 在`study_id`字段上创建索引，优化通过检查记录ID查询其关联分析任务的性能。
  - 在`user_id`字段上创建索引，优化通过用户ID查询其创建的所有分析任务的性能。
  - 在`status`和`created_at`字段上创建复合索引，这对于查询特定状态（如'PROCESSING'或'FAILED'）的任务，并按创建时间排序（例如，获取最新的待处理任务）非常高效。

## 模型关联关系

AnalysisTask模型通过外键与Study和User模型建立了明确的关联关系：

- **与Study模型的关联**: 一个分析任务属于一个检查记录（Study）。在`server/models/index.js`中，通过`AnalysisTask.belongsTo(Study, { foreignKey: 'study_id', as: 'study' })`定义了这种关系。这意味着可以通过`task.study`访问其关联的检查记录。反之，一个检查记录可以有多个分析任务，通过`Study.hasMany(AnalysisTask, { foreignKey: 'study_id', as: 'analysis_tasks' })`定义。
- **与User模型的关联**: 一个分析任务由一个用户创建。在`server/models/index.js`中，通过`AnalysisTask.belongsTo(User, { foreignKey: 'user_id', as: 'user' })`定义了这种关系。这意味着可以通过`task.user`访问创建该任务的用户信息。反之，一个用户可以创建多个分析任务，通过`User.hasMany(AnalysisTask, { foreignKey: 'user_id', as: 'analysis_tasks' })`定义。

## 任务ID生成逻辑

AnalysisTask模型通过Sequelize的`beforeCreate`钩子在创建新记录前自动生成`task_id`。其逻辑如下：

1.  钩子函数`AnalysisTask.beforeCreate`会在每次创建新任务实例前被调用。
2.  函数首先检查`task.task_id`是否已存在，如果不存在（即为`null`或`undefined`），则执行生成逻辑。
3.  生成逻辑结合了时间戳和随机字符串：
    -   `const timestamp = Date.now();` 获取当前的Unix时间戳（毫秒）。
    -   `const random = Math.random().toString(36).substring(2, 8);` 生成一个随机数，转换为36进制字符串，并截取第2到第8个字符，得到一个6位的随机字符串。
4.  最后，将前缀`"TASK"`、时间戳和随机字符串拼接起来，形成最终的`task_id`，例如`TASK1701234567890abc123`。这种组合方式极大地降低了生成重复ID的可能性，确保了任务ID的全局唯一性。
