## 一、后端能力新增

### 1.1 新增批量接口

- 新增 `POST /api/analysis-tasks/batch`。
- 鉴权方式与现有分析任务接口一致（`Bearer Token`）。
- 使用 `multer` 多文件上传，字段为 `images`，单次最多 10 张。
- 接口支持“部分成功”：单个文件失败不阻塞其它文件创建。

### 1.2 请求字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `images` | `File[]` | 是 | 医学影像文件数组（最多 10 张） |
| `patientName` | `string` | 是 | 患者姓名 |
| `patientId` | `string` | 是 | 患者业务号 |
| `studyDate` | `string` | 是 | 检查日期（ISO date） |
| `modality` | `string` | 是 | 检查方式 |
| `description` | `string` | 否 | 检查描述 |
| `priority` | `string` | 否 | 优先级（`normal`/`urgent`/`emergency`） |
| `model_version` | `string` | 否 | 模型版本 |

### 1.3 响应结构（支持部分成功）

```json
{
  "success": true,
  "message": "批量任务创建完成，成功 8 条，失败 2 条",
  "data": {
    "batchId": "batch_xxx",
    "summary": {
      "total": 10,
      "created": 8,
      "failed": 2
    },
    "items": [
      {
        "index": 0,
        "originalFilename": "a.jpg",
        "studyDbId": 101,
        "studyId": "study_xxx",
        "imageId": 501,
        "taskId": "task_xxx",
        "status": "PENDING"
      },
      {
        "index": 1,
        "originalFilename": "b.jpg",
        "status": "FAILED",
        "error": "创建任务失败"
      }
    ]
  }
}
```

### 1.4 关键处理策略

- 对每张影像独立事务创建 `Study`、`StudyImage`、`AnalysisTask`。
- 失败文件会执行上传文件清理，避免残留脏文件。
- 创建成功后异步触发分析流程，不阻塞批量接口响应。
- 对外返回 `summary + items`，前端可直接展示批次级与文件级状态。

## 二、前端上传页改造

### 2.1 交互改动

- 上传页由单图流程扩展为多图批量流程。
- 支持多选与追加上传，界面明确提示“最多 10 张”。
- 批量提交时展示进度与结果摘要，失败项单独提示。

### 2.2 提交链路

- `UploadPage.vue` 在上传完成后调用 `analysisTaskAPI.createBatchTasks`。
- 成功后按返回的 `batchId` 与 `summary/items` 进行结果反馈。
- 对常见错误（404 接口不存在、网络中断）给出明确提示文案。
