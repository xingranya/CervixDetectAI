## 环境要求

在开始安装 CervixDetectAI 之前，请确保您的系统满足以下环境要求：

- **Node.js**: 16.x 或更高版本（推荐使用 Node.js 20+）
- **包管理工具**: Bun / npm
- **数据库**: MySQL 5.7 或 8.0 版本
- **操作系统**: Windows、macOS 或 Linux
- **磁盘空间**: 至少 1GB 可用空间（用于代码、依赖和上传文件存储）

您可以通过以下命令验证环境是否已正确安装：

```bash
node --version
bun --version
mysql --version
```

## 数据库配置

### 1. 创建数据库

首先，在您的 MySQL 服务器中创建一个新数据库，用于存储 CervixDetectAI 的所有数据。建议使用 UTF8MB4 字符集以支持中文和特殊字符。

执行以下 SQL 命令：

```sql
CREATE DATABASE cervix_detect_ai CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2. 配置数据库连接

进入 `server` 目录，复制 `.env.example` 文件为 `.env`（如果不存在），并根据您的数据库信息进行配置。

编辑 `server/.env` 文件，设置以下数据库相关参数：

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=cervix_detect_ai
```

这些配置将被 `server/config/database.js` 文件读取，用于建立与数据库的连接。

## 数据库初始化

完成数据库配置后，需要运行初始化脚本来创建所有数据表并插入默认数据。

### 执行初始化脚本

在项目根目录下，进入 `server` 子目录并运行初始化脚本：

```bash
cd server
node scripts/init-database.js
```

该脚本会执行以下操作：

- 测试数据库连接
- 同步所有模型结构到数据库（创建表）
- 检查并创建默认管理员账户（如果不存在）

初始化成功后，您将看到类似以下输出：

```
✅ 数据库连接成功!
✅ 数据库结构同步完成!
✅ 管理员账号创建成功!
   邮箱: admin@cervixdetectai.com
   密码: admin123456
🎉 数据库初始化完成!
```

## 短信服务可选配置

如果您需要使用手机号登录、注册或找回密码功能，可以配置阿里云短信服务。

### 1. 配置环境变量

在 `server/.env` 文件中添加以下配置项：

```env
ALIYUN_ACCESS_KEY_ID=your_access_key_id
ALIYUN_ACCESS_KEY_SECRET=your_access_key_secret
ALIYUN_SMS_SIGN_NAME=your_sign_name
ALIYUN_SMS_TEMPLATE_CODE=100001
```

### 2. 创建短信验证码表

运行以下脚本创建 `sms_codes` 表，用于存储短信验证码记录：

```bash
cd server
node scripts/create-sms-table.js
```

该表将包含验证码、过期时间、使用状态等信息，支持登录、注册、重置密码等多种场景。

## 前端安装与启动

### 0. 安装 Bun 环境

本项目使用 Bun 作为包管理器和极速运行环境，请先确保系统已全局安装 Bun：

```bash
# macOS / Linux / WSL
curl -fsSL https://bun.com/install | bash

# Windows (PowerShell)
powershell -c "irm bun.sh/install.ps1 | iex"
```

### 1. 安装前端依赖

在项目根目录执行以下命令安装前端所需的所有依赖：

```bash
bun install
```

### 2. 配置前端环境变量

确保根目录下的 `.env` 文件已正确配置 API 基础地址：

```env
VITE_API_BASE_URL=http://localhost:3000/api
```

此配置将被 `src/boot/axios.ts` 读取，用于设置 HTTP 请求的基础 URL。

### 3. 启动前端开发服务器

运行以下命令启动前端开发服务器：

```bash
bun run dev
```

前端应用将在 `http://localhost:9000` 启动，默认使用 Quasar 的开发服务器。

### 4. 开发环境 API 代理配置

在本地开发环境中，前端和后端通常运行在不同的端口上（前端 9000，后端 3000），这会导致跨域请求问题。为了解决这个问题，项目已在 `quasar.config.ts` 中配置了开发服务器代理。

该代理配置的作用是将所有以 `/api` 开头的请求自动转发到后端服务器 `http://localhost:3000`，从而避免跨域限制。

相关配置位于 `quasar.config.ts` 文件的 `devServer.proxy` 部分：

```ts
devServer: {
  open: true,
  proxy: {
    '/api': {
      target: 'http://localhost:3000',
      changeOrigin: true,
      ws: true
    }
  }
}
```

- `target`: 指定代理目标地址，即后端服务地址
- `changeOrigin`: 设置为 `true` 以更改请求头中的 origin，使后端服务器能正确处理请求
- `ws`: 支持 WebSocket 代理，确保实时通信功能正常

**此代理仅在开发环境（`bun run dev`）下生效，生产环境通过 Nginx 等反向代理实现。**

## 后端安装与启动

### 1. 安装后端依赖

进入 `server` 目录并安装后端依赖：

```bash
cd server
bun install
```

### 2. 配置后端环境

确保 `server/.env` 文件已完整配置，包括数据库、JWT 密钥和服务器端口等：

```env
PORT=3000
JWT_SECRET=your-secret-key-change-in-production-min-128-bits
JWT_ACCESS_EXPIRATION=1h
JWT_REFRESH_EXPIRATION=7d
```

### 3. 启动后端服务

启动后端服务器：

```bash
bun start
# 或使用开发模式（支持热重载）
bun run dev
```

后端服务将在 `http://localhost:3000` 启动，并自动连接数据库。您可以通过访问 `http://localhost:3000/health` 来检查服务状态。

## 生产环境构建与部署

### 1. 构建前端生产版本

在项目根目录执行构建命令：

```bash
bun run build
```

构建产物将输出到 `dist/spa` 目录，包含所有静态资源文件。

### 2. 部署建议

**推荐部署架构**：

- 使用 Nginx 作为前端静态文件服务器和反向代理
- 后端服务通过 PM2 或 Docker 容器化部署
- 数据库独立部署，确保高可用性

**Nginx 配置示例**：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /path/to/dist/spa;
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**生产环境注意事项**：

- 修改 JWT 密钥，确保足够复杂（至少 128 位）
- 将 `NODE_ENV` 设置为 `production`
- 配置 HTTPS 以保证数据传输安全
- 定期备份数据库
- 监控服务器资源使用情况

## 常见问题与故障排除

### 数据库连接失败

- 检查 `server/.env` 中的数据库配置是否正确
- 确认 MySQL 服务正在运行
- 验证数据库用户名和密码是否有权限访问指定数据库

### 端口冲突

- 修改 `server/.env` 中的 `PORT` 值
- 确保前端和后端端口不冲突（默认前端 9000，后端 3000）

### 短信服务无法发送

- 检查阿里云 AccessKey 是否正确
- 确认短信签名和模板代码已通过审核
- 查看控制台日志中的错误信息

### 默认管理员无法登录

- 确认数据库初始化脚本已成功执行
- 检查 `users` 表中是否存在 `admin@cervixdetectai.com` 用户
- 尝试重置密码或重新运行初始化脚本
