## 用户表（users）

该表存储系统用户的基本信息和认证凭据，是系统权限控制的核心。

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 用户唯一标识 |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 用户名，用于登录 |
| email | VARCHAR(100) | UNIQUE, NOT NULL | 邮箱地址，用于登录和找回密码 |
| password_hash | VARCHAR(255) | NOT NULL | bcrypt加密后的密码哈希值 |
| real_name | VARCHAR(100) | NULL | 真实姓名 |
| phone | VARCHAR(20) | NULL | 手机号码 |
| avatar_url | VARCHAR(500) | NULL | 头像文件存储路径 |
| role | ENUM('admin', 'doctor', 'user') | NOT NULL, DEFAULT 'user' | 用户角色 |
| status | ENUM('active', 'disabled') | NOT NULL, DEFAULT 'active' | 账号状态 |
| last_login_at | DATETIME | NULL | 最后登录时间 |
| last_login_ip | VARCHAR(45) | NULL | 最后登录IP地址 |

**索引设计**：
- 主键索引：id
- 唯一索引：username, email
- 普通索引：status, created_at

**业务逻辑**：
- 密码通过bcrypt进行哈希存储，确保安全性
- `role`字段控制用户权限，`admin`拥有最高权限，`doctor`可进行诊断，`user`为普通用户
- `status`字段用于账号启用/禁用控制
- 提供`validatePassword`实例方法验证密码，`setPassword`方法生成哈希
- 在`beforeSave`钩子中自动加密密码，防止明文存储

## 患者表（patients）

该表存储患者的基本信息和医疗档案元数据，支持医疗数据隐私保护。

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 患者唯一标识 |
| patient_id | VARCHAR(50) | UNIQUE, NOT NULL | 患者编号（业务ID） |
| name | VARCHAR(100) | NOT NULL | 患者姓名 |
| gender | ENUM('male', 'female', 'other') | NOT NULL | 性别 |
| birth_date | DATEONLY | NULL | 出生日期 |
| phone | VARCHAR(20) | NULL | 联系电话 |
| id_card | VARCHAR(50) | NULL | 身份证号（加密存储） |
| address | VARCHAR(500) | NULL | 联系地址 |
| emergency_contact | VARCHAR(100) | NULL | 紧急联系人 |
| emergency_phone | VARCHAR(20) | NULL | 紧急联系电话 |
| medical_history | TEXT | NULL | 既往病史 |
| allergies | TEXT | NULL | 过敏信息 |
| created_by | BIGINT | NOT NULL, FOREIGN KEY | 创建者用户ID |

**索引设计**：
- 主键索引：id
- 唯一索引：patient_id
- 普通索引：name, phone, created_by

**业务逻辑**：
- `patient_id`通过`beforeCreate`钩子自动生成，格式为`P`+时间戳+3位随机数
- `id_card`字段在应用层进行加密存储，保护患者隐私
- `created_by`外键关联`users`表，记录创建者信息

| patient_id | BIGINT | NOT NULL, FOREIGN KEY | 关联患者ID |
| user_id | BIGINT | NOT NULL, FOREIGN KEY | 创建者用户ID |
| study_date | DATETIME | NOT NULL | 检查日期 |
| study_type | VARCHAR(50) | NOT NULL | 检查类型（宫颈细胞学检查、阴道镜检查等） |
| description | TEXT | NULL | 检查描述 |
| department | VARCHAR(100) | NULL | 科室 |
| doctor_name | VARCHAR(100) | NULL | 医生姓名 |
| clinical_diagnosis | TEXT | NULL | 临床诊断 |

## JSON字段与ENUM类型说明

### JSON字段使用场景
- **recommendations**: 存储结构化的医疗建议，如`[{"type": "follow_up", "interval": "3个月", "content": "建议3个月后复查"}]`
- **biomarkers**: 存储生物标志物检测结果，如`{"HPV": "阳性", "p16": "阳性", "Ki67": "高表达"}`
- **suspicious_areas**: 存储图像中可疑区域的坐标数据，用于定位病变
- **raw_output**: 存储AI模型的原始输出，便于调试和算法优化
- **dicom_metadata**: 存储DICOM文件的关键元数据，如患者ID、检查日期、设备型号等

### ENUM类型安全控制
- **role**: 限制用户角色为`admin`、`doctor`、`user`，确保权限安全
- **risk_level**: 标准化风险评估为`low`、`medium`、`high`、`critical`
- **report_type**: 区分`preliminary`（初步）、`final`（正式）、`supplementary`（补充）报告
- **status**: 通过预定义状态值确保数据一致性，避免无效状态
